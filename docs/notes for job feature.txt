
  Job Feature - Functional Description	



  Phase 1: Core structure

  1. Job Creation Dialog - Modal with Job Name, Company        
  selection, Initial Notes.
	- Company: Dropdown containing existing companies created by the user (from companies table). As the user types, a search is triggered to display matching companies. There must always be an option to create a new company (the company creation workflow will be defined separately).
	- Job Title: Free text field allowing the user to enter a title.
	- Initial Notes: Free text field allowing the user to enter job notes, which may include client call notes, unstructured or unordered notes, or even the job description.
  2. Phase Navigator Component - Fixed top bar with 6 clickable phases (Define, Source, Review, Reach, Assess, Submit): This bar must be clean, aesthetic and minimalistic.
  3. Phase Router - Handle navigation between phases and maintain state
  4. Base Job Layout - Container with navigator + dynamic content area

  





  Phase 2: Individual Phase Components

  Overall structure:
  	- On the job page, there will be a phase navigator containing the content for each phase. In some cases, each phase may also include subviews. Every phase must have its own Edit and Save buttons to preserve data during phase navigation while editing or creating a job.
	- At the top level, there must also be global Edit and Save buttons to save the job itself; these actions will update the jobs database. Additionally, if the user attempts to leave the page with unsaved changes, the app must display an appropriate popup warning.


  Define Phase (3 sub-views accessible through tabs):
  - Initial data (lets call this tab Initial Data): 
	- Form with Company, Job Title, Initial Notes: These forms must display the data entered by the user in the job creation dialog. Include Edit and Save buttons to allow modifications and saving of this data.
  - Role Analysis: 
	- This subview contains two sections: Attributes and Requirements. 
	- Both sections will be empty by default at job creation. Their content can be generated by letting the user manually input the attributes or by clicking the "Generate" button, which triggers an external API. The generated content will then be editable by the user.  
	- Specific details about this functionality UI and API will be provided later; there is no need to focus on it for now.
	- Each section (Attributes and Requirements) will include a copy function to allow users to copy the generated or created content in plain text format. Further details will be provided later.
 - Job Description: 
	- This subview allows the user to generate a job description based on initial notes content and attributes. The subview contains checkboxes to let the user pick how to build the job description. The job description field must have the copy function to allow users copy the content and an edit button to allow users edit the generated data. (Checkboxes will serve as inputs for the API that will generate the job description. API details will be provided separately in another stage)
	- Job description field is empty by default at job creation

  Source Phase:
  - This section contains 2 sections: "LinkedIn boolean query" and "Pre-vetted candidates"
  - LinkedIn Boolean query: This section contains an editable text field that is empty by default at job creation. Its content can be generated by either clicking on a "Generate" button that will triggeer an external API that will return the content or by letting the user manually input the query. This field must have the copy function to allow users copy the content and an edit button to allow users edit the generated data. If no attributes are loaded in the Role Analysis subview, the query cannot be generated.
  - Pre-vetted Candidates Request section: This section will include a subtitle explaining that it allows the user to access and view pre-vetted candidates who are a fit for the job. It will also contain a button to submit the request. Details of the workflows triggered by this button will be provided later; no need to focus on this for now.


  Review Phase:
  - This section allows the user to compare candidates against the job to assess fit. It contains the following subsections:
  	- Candidate input field: Dropdown listing candidates created by the user (from the candidates table). As the user types, a search is triggered to display matching candidates. There must always be an option to create a new candidate (the candidate creation workflow will be defined separately).
 	- Analysis type checkboxes (PDF/LinkedIn): These are checkboxes used to indicate how the fit analysis should be run. These variables will serve as inputs for an API, which will be shared at a later stage.
	- "Run Analysis" button: This button triggers an API, the details of which will be provided later.
        - At the bottom, there will be a section to display the analysis results in a clear, intuitive, and visually appealing way based on the API response. No need to focus on this for now.

  Reach Phase:
  - This section allows the user to craft email messages for reaching out to candidates. Emails are generated by AI based on the selected template.
  - Candidate and Template Selection:  Dropdowns to select the candidate (same functionality as the candidate dropdown described above) and the email template to use.
  - Message field, Generate button and Copy Functionality: An editable field with an Edit button. A separate "Generate" button triggers an API that generates the message using AI, and the output is displayed in this field. The user can edit the generated content, and a copy icon must be available to copy the message. API details will be provided at a later stage.
  - This section will not have save functionality for now, meaning no information related to this phase will be stored in the database.


  Assess Phase (2 Sub-Views):
  - Interview Questions: This subview allows the user to generate questions based on the job details. Each question must be editable. A copy icon must be available to copy the questions in plain text format, following guidelines that will be provided later. The "Generate" button triggers an API to generate the questions. API details and response format will be shared at a later stage.
 - Full Interview Review: This section allows the user to generate an evaluation based on the interview transcript provided as input. It includes the following components:
    - Candidate Input: A dropdown to select a candidate (same functionality as the candidate dropdown described above).
    - Transcript Area: An input field for the user to paste the interview transcript.
    - Results: A field displaying the evaluation of the interview transcript based on specific guidelines. The displayed content will be based on the API response. API and UI details for this section will be provided at a later stage.

 
Submit Phase:
  - This phase allows the user to craft email messages for reaching out to companies for submitting/presenting candidates or for scheduling interviews
  - Candidate Input: A dropdown to select a candidate (same functionality as the candidate dropdown described above).
  - Company Input: A dropdown to select a company (same functionality as the candidate dropdown described above).
  - Template Selection: Dropdown to pick the template to use
  - Message field, Generate button and Copy Functionality: An editable field with an Edit button. A separate "Generate" button triggers an API that generates the message using AI, and the output is displayed in this field. The user can edit the generated content, and a copy icon must be available to copy the message. API details will be provided at a later stage.
 - This section will not have save functionality for now, meaning no information related to this phase will be stored in the database.
