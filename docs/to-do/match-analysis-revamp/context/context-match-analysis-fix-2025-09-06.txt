  1. Eliminate industry

  - Why: Industry skills like "Healthcare," "Fintech," "E-commerce" are too broad and don't provide actionable matching criteria
  - Alternative: Use job descriptions and company context instead
  - MVP Impact: Removing reduces complexity without meaningful matching loss

  2. Eliminate role (confirmed)

  - Why: As discussed, creates semantic overlap with technical skills
  - Example Problem: "Python Developer" vs "Python" matching complexity
  - MVP Impact: Major simplification of matching algorithms

  3. Eliminate technology_domain

  - Why: Overlaps heavily with technical_skill categories
  - Example: "Frontend Development" as domain vs React/Vue as technical skills
  - Alternative: The skill registry already handles hierarchical relationships (Frontend Development → React, Vue, Angular)
  - MVP Impact: Registry system is more precise and maintainable

  Simplified Final Structure:
  // MVP Skill Types (3 types only)
  const CORE_SKILL_TYPES = {

    soft_skill: "Soft skill",         // Leadership, Communication  
    certification: "Certification"    // AWS Certified, PMP
  }

  Benefits of this approach:
  1. Cleaner matching logic: Only 3 skill types to handle
  2. Registry-driven relationships: Skill registry handles hierarchies and aliases
  3. Reduced complexity: Fewer edge cases in matching algorithms
  4. Better maintainability: Clear separation of concerns

  The skill registry already provides the sophisticated relationship mapping you need (parent/child/aliases/qualifiesFor), making additional skill type categories redundant for MVP
  purposes.
